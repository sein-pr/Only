# SHOPY E-COMMERCE PROJECT - COMPREHENSIVE CODE DOCUMENTATION
# =============================================================

## PROJECT OVERVIEW
Shopy (formerly "Only") is a full-featured e-commerce web application built with Flask (Python web framework). 
It provides a complete online shopping experience with user authentication, product management, shopping cart, 
payment processing, and seller dashboard functionality.

## TECHNOLOGY STACK
- **Backend**: Python 3.11, Flask 2.3.3, SQLAlchemy (ORM)
- **Database**: PostgreSQL 15
- **Frontend**: HTML5, CSS3, Bootstrap 5.3, JavaScript, Font Awesome
- **Payment**: Stripe API integration
- **Email**: Flask-Mail with SMTP
- **Deployment**: Docker, Docker Compose, Nginx
- **Security**: CSRF protection, password hashing, session management

## MAIN APPLICATION FILE: app.py
================================

### CONFIGURATION & SETUP (Lines 1-68)
- **Environment Variables**: Uses python-dotenv to load configuration from .env file
- **Database Configuration**: Supports both local PostgreSQL and Heroku PostgreSQL
- **Mail Configuration**: SMTP settings for email notifications (password reset, order confirmations)
- **Stripe Configuration**: Payment processing API keys
- **File Upload**: Configures upload directory for product images and user avatars

### DATABASE MODELS (models/models.py)
=====================================

#### User Model (Lines 7-49)
- **Core Fields**: id, username, email, password_hash, role, created_at
- **Profile Fields**: first_name, last_name, phone, address, avatar_url
- **Structured Address**: address_line1, city, state_province, postal_code, country
- **Company Fields**: For sellers - company_name, company_description, company_logo_url
- **Relationships**: One-to-many with orders and products

#### Category Model (Lines 51-57)
- **Fields**: id, name, description
- **Purpose**: Organizes products into categories (Electronics, Clothing, etc.)

#### Product Model (Lines 60-77)
- **Core Fields**: id, name, description, price, stock_quantity, image_url
- **Advanced Features**: additional_images (JSON array), status (active/inactive)
- **Foreign Keys**: category_id, seller_id
- **Relationships**: One-to-many with order_items

#### Order & OrderItem Models (Lines 79-101)
- **Order**: order_number, total_amount, status, user_id
- **OrderItem**: quantity, price, order_id, product_id
- **Status Flow**: pending → confirmed → processing → shipped → delivered

#### CartItem Model (Lines 103-112)
- **Session Management**: Uses session_id for guest users and user_id for logged-in users
- **Features**: quantity, save_for_later functionality
- **Purpose**: Manages shopping cart items before checkout

#### Wishlist Model (Lines 115-127)
- **Purpose**: Allows users to save products for later purchase
- **Constraints**: Unique combination of user_id and product_id

#### ProductView Model (Lines 129-141)
- **Analytics**: Tracks product views for seller analytics
- **View Types**: quick_view, full_detail
- **Guest Support**: Tracks IP address and user agent for non-logged-in users

#### PasswordResetToken Model (Lines 143-152)
- **Security**: Secure token-based password reset system
- **Expiration**: Tokens expire after 1 hour
- **Usage Tracking**: Prevents token reuse

### FORM HANDLING (forms/)
=========================

#### forms.py (Basic Forms)
- **LoginForm**: Email and password validation
- **RegisterForm**: Username, email, password, role selection
- **ProductForm**: Product creation/editing with image upload

#### profile_forms.py (Advanced Profile Management)
- **ProfileForm**: Comprehensive user profile with structured address fields
- **Country Codes**: Extensive list of international phone country codes
- **Company Fields**: Separate company information for sellers
- **File Uploads**: Avatar and company logo support

#### password_reset_forms.py (Security Forms)
- **ForgotPasswordForm**: Email input for password reset request
- **ResetPasswordForm**: New password with confirmation validation

### AUTHENTICATION SYSTEM (Lines 120-392)
=========================================

#### Helper Functions
- **get_session_id()**: Generates unique session IDs for cart management
- **get_cart_count()**: Returns number of items in user's cart
- **login_required**: Decorator for protected routes
- **seller_required**: Decorator for seller-only routes

#### Login Route (Lines 143-185)
- **Password Verification**: Uses Werkzeug's check_password_hash
- **Session Management**: Stores user_id, username, role in session
- **Cart Transfer**: Merges guest cart with user cart upon login
- **Role-based Redirect**: Sellers go to dashboard, buyers to home

#### Registration Route (Lines 296-341)
- **Duplicate Check**: Prevents duplicate usernames/emails
- **Password Hashing**: Uses Werkzeug's generate_password_hash
- **Automatic Login**: Logs in user after successful registration

#### Password Reset System (Lines 187-391)
- **Token Generation**: Creates secure UUID tokens with 1-hour expiration
- **Email Integration**: Sends HTML-formatted reset emails
- **Security**: Prevents token reuse and validates expiration

### PRODUCT MANAGEMENT (Lines 599-1534)
======================================

#### Shop Route (Lines 615-689)
- **Filtering**: Category, search, price range filters
- **Sorting**: Price (low/high), name, newest
- **Pagination**: 9 items per page for mobile optimization

#### Product Detail Route (Lines 691-739)

- **Duplicate Product**: Creates copy with "COPY of..." prefix

=========================================

#### Cart Management
- **Session-based**: Works for both guests and logged-in users
- **Save for Later**: Items can be saved without purchasing

- **/api/update-cart-item**: Quantity updates

### API ENDPOINTS SUMMARY
========================

#### Authentication
- POST /login, /register, /logout
- POST /forgot-password, /reset-password/<token>

#### Product Management
- GET /shop (with filtering/sorting)
- GET /product/<id>
- POST /seller/add-product, /seller/edit-product/<id>
- DELETE /seller/delete-product/<id>

#### Cart & Checkout
- GET /cart
- POST /add-to-cart/<id>
- POST /create-payment-intent
- POST /process-stripe-payment

#### API Endpoints
- /api/cart-items, /api/cart-count
- /api/wishlist/add/<id>, /api/wishlist/remove/<id>
- /api/product/<id>/quick-view
- /api/seller/sales-trend

### DATABASE RELATIONSHIPS
=========================

#### User Relationships
- One-to-Many: User → Orders, User → Products (as seller)
- One-to-Many: User → Wishlist, User → ProductViews

#### Product Relationships
- Many-to-One: Product → Category, Product → User (seller)
- One-to-Many: Product → OrderItems, Product → CartItems

#### Order Relationships
- Many-to-One: Order → User
- One-to-Many: Order → OrderItems
